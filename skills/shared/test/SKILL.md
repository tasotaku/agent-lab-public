# /test — テスト検証スキル

実装完了前確認のステップ2。「動くはずです」で済ませず、実際にテストを動かして確認する。

## ステップ1: 変更スコープを把握する

```bash
# コミット済み変更
git diff @{u}.. --stat 2>/dev/null || git diff origin/HEAD... --stat 2>/dev/null

# 未コミット変更
git diff HEAD --stat
```

変更されたファイルと、そこで何が変わったかを把握する。

## ステップ2: テストすべき振る舞いを列挙する

以下の3グループで番号付きリストを出す。推測せず、差分から読み取れる事実に基づく。

- **(a) ハッピーパス**: 正常系の主要な動作
- **(b) エッジケース**: 境界値・空入力・最大値・型の境界など
- **(c) エラーパス**: 失敗すべき入力、例外が出るべきケース

リストが出たら、次のステップに進む前に一度見直す。「これは本当に今回の変更に関係するか？」

## ステップ3: テストランナーを自動検出する

以下の順で検出する：

1. `package.json` の `scripts.test` → `npm test` / `npx jest` / `npx vitest`
2. `pytest.ini` / `pyproject.toml` の `[tool.pytest]` → `pytest`
3. `go.mod` → `go test ./...`
4. `Makefile` の `test` ターゲット → `make test`
5. `Cargo.toml` → `cargo test`

テストランナーが見つからない場合: BLOCKED を報告し、セットアップ手順を提案する。

## ステップ4: 既存テストとのマッピング

テストファイルを探す：

```bash
find . -type f \( \
  -name "*.test.ts" -o -name "*.test.tsx" -o -name "*.test.js" \
  -o -name "*.spec.ts" -o -name "*.spec.js" \
  -o -name "*_test.py" -o -name "test_*.py" \
  -o -name "*_test.go" \
\) -not -path "*/node_modules/*" -not -path "*/.git/*" | head -50
```

ステップ2の各項目に対して：
- 既存テストがカバーしているなら `✅ covered`
- カバーされていないなら `❌ gap`

カバーされている項目のテストを実行する（プロジェクト全体でなく、関連するファイルに絞る）。

## ステップ5: ギャップを埋める

`❌ gap` の項目に対してテストを書く。

- 配置先: `tests/temp/` （なければ作成。`.gitignore` に追加されていなければ追加する）
- ファイル名: `test_<feature>_temp.py` / `<feature>.temp.test.ts` など、temp であることがわかる名前
- テストは最小限に。実装を証明するのが目的、網羅的なスイートを書く必要はない

書いたら実行する。失敗したら：
1. 失敗メッセージを読んで原因を特定する
2. 実装のバグなら実装を直す、テストの期待値が間違いならテストを直す
3. 再実行する
4. 全部通るまで繰り返す

## ステップ6: レポートを出す

```
## Test Coverage: <何が変わったか1行>

### テストすべき振る舞い
1. ✅/❌ <振る舞い>
2. ...

### 既存テスト実行結果
<テスト出力のサマリー（passed/failed 件数と、失敗があれば内容）>

### 新規作成テスト（あれば）
- `tests/temp/<ファイル名>`: <何をテストしているか>

### 新規テスト実行結果
<テスト出力>

### Verdict: PASS | FAIL | BLOCKED
```

- **PASS**: 全テスト（既存＋新規）が通った
- **FAIL**: テストが落ちている。修正してサイクルを回す（自力で直せる場合は直してから再報告）
- **BLOCKED**: テストランナーがない、環境が壊れているなど、テスト実行自体ができない

## 注意事項

- **「シンプルな変更だから省略」はしない。** 必ず振る舞いリストだけでも出す。
- **既存テストを壊したまま PASS にしない。** 関連するテストスイート全体が通ることを確認する。
- **`tests/temp/` は使い捨て前提。** push しない。セッション終了後に削除されても問題ない設計にする。
- **型チェック・lint はここではしない。** それはステップ1（静的チェック）の仕事。
